# 本次部署前检查

结论：构建产物可用于测试发布。**不能把本版本视为已经完成“最新 SAP 自动同步、匹配、异常核对”的正式版本。** 本次没有执行线上部署、提交代码、推送仓库或修改正式 Firebase 数据。

## 已修复

- 缺少 SAP 料号时，详情比对曾回退显示总表料号，容易误认为 SAP 中已有对应数据。现在明确显示缺失，清空的业务料号也保留为空。
- 远端插入或删除列后，当前选中单元格和列筛选可能仍按旧索引定位。现在按稳定列 ID 保持选中位置，结构变化时清除过期筛选，原单元格被删除时清空选择。
- 丢弃本地修改并载入云端版本时，清除旧编辑状态，避免继续提交旧单元格草稿。
- 异常／数据核对页面增加参考数据范围说明，避免把历史参考数据的核对误当成最新 SAP 实时核对。
- 应用源码中的静态检查错误已修正；Excel 控制字符转义及 Firebase 非法键检查保留。

## 正式使用前的缺口

1. **最新 SAP 数据接入未完成。** Python 脚本的目标是原始快照区；网页读取的是 `workspaces/excel-20260904` 的来源与协作版本，没有消费 `sap/current`。云端当前也没有该路径的成功同步快照。需要在目标内网电脑验证取数，并实现经过确认的单据行匹配与单位／数量规则后，才能宣称核对的是最新 SAP。
2. **仍是公开读写测试配置。** `src/runtime-config.mjs` 开启了该模式。正式权限隔离尚未完成；不能仅把这个开关关闭，因为现有登录试点是另一种数据模式。应同时接入正确的身份认证、工作区访问权限和数据库规则。
3. **本次真实云端写入联动未实测。** 自动审批拒绝了把完整业务源数据复制到临时 Firebase 工作区进行写入测试的操作。该操作未执行。已完成本地模拟写入／冲突测试和云端只读检查，不能以此替代真实双端写入验证。
4. **代码尚未提交发布。** 当前分支为 `main`，存在大量已修改／未跟踪的功能文件。通过连接 GitHub 的部署入口发布前，必须将需要发布的最新文件提交并推送到所选分支；本地构建成功不会自动更新远端代码。

## 发布配置

现有 `render.yaml` 配置为静态站点，构建命令 `npm ci && npm run build`，发布目录 `dist`，Node 24。使用对应的 Static Site 流程，不使用遗留的 `npm start`：该命令引用当前 Vue 构建不会生成的 `dist/server/wrangler.json`。

只发布 `dist`；不要上传本地 `secrets`、同步日志或 SAP 凭证。现有原始 Excel 模板和源数据清单是网页导出／初始化所需的静态资源，会随站点提供访问；正式访问策略也需要覆盖这一点。

本次未执行浏览器逐项交互测试、目标电脑的真实 SAP 网络测试或 Render 线上验收。上线后仍需在实际站点确认下载、保存刷新及跨设备同步。
