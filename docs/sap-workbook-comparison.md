# SAP 与总表 PO 比对

异常与待办、数据中心现在按总表当前值核对 SAP PO、订单行及物料。PO 与订单行不一致分别生成异常；总表行号空白或为占位符时单列为“总表订单行缺失”，双方都有行号且数值不同才生成订单行不一致；缺少唯一 SAP 参考关联时生成待关联事项，不推断为 SAP 中不存在该订单。

- SAP PO 和订单行分别保存在 `sapPo`、`sapItem`，来自导入记录的 `sapOriginal.EBELN` 和 `sapOriginal.EBELP`。旧工作区在加载时只读原导入批次的 `payloadJson`，按不可变记录 ID 补齐内存中的参考字段。无需覆盖原工作区或重新初始化 Firebase。
- Excel 侧来自当前 `importFields.po` 和 `importFields.line`。空白、`/`、`—`、`-` 都按缺失处理；纯数字标识忽略前导零和两端空白，但展示与导出保留原文。多 PO 文本不会擅自选择其中一个作为匹配结果。
- 不因 PO 编辑重新关联其他源记录。已完成、已取消行也参与比对。新增总表记录先显示待关联，不擅自用同料号猜测 SAP 订单。
- 修改保存后使用现有共享工作区机制重新计算异常。修正一致后异常自动关闭，再次变化会重新打开并保留跟进记录。仅填写备注不能关闭 PO 差异。读取参考数据失败时显示读取失败事项，已有 PO 差异不会误判通过；刷新页面可以重试读取。
- 异常列表以独立列并列显示双方 PO、订单行和料号，同时存在的 PO、料号差异都会高亮。六个表头均有 Filter 按钮，使用表头下拉搜索、多选、跨列叠加和清除筛选；筛选不更改业务记录。异常搜索支持双方 PO、订单行和料号；订单详情与导出均保留双方字段。异常 Excel 为 22 列，按当前筛选导出全部结果。
- 原导入的 `sap_link`、`material` 警告已由动态规则替代，避免修正后旧初始化警告仍保持未处理。数量、价格等其他原有规则保留。

## 验证与边界

2026-09-11 通过现有 Firebase 只读加载验证：1,253 行，793 行具有 SAP 参考匹配、460 行未建立唯一关联、0 行参考读取失败。当时检测到 PO 差异 0 条、订单行缺失 151 条、实际订单行不一致 0 条、料号差异 60 条。这些是检查时的数据，后续编辑会改变数量。

自动化覆盖导入适配、旧批次读取、前导零与空值、PO/行修改、完成记录、跟进与自动关闭、参考失败、Firebase 加载及总表更新联动、导出双方字段和界面筛选。全部测试使用本地模拟写入；云端仅做读取。

当前比较的是已导入的历史 SAP 参考数据。后续 `sap/current` 原始快照尚未自动接入工作区；本功能不宣称核对最新 SAP，也不向 SAP 写回总表编辑。
