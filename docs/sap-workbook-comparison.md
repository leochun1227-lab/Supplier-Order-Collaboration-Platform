# SAP 与总表 PO 比对

异常、数据中心按最新导入总表的当前 PO＋物料核对 SAP。2026-10-13 起，确认对应记录后自动修正总表 Line No，行号缺失或不一致不再单列异常；PO 存在但物料不匹配时只报物料异常，保留总表原行号。缺少唯一 SAP 参考关联时生成待关联事项，不猜选记录。

- 旧工作区先按不可变记录 ID 读取原导入批次的 SAP 关联，然后读取 Firebase `sap/current` 指向的 PO 表。每 15 秒检查新快照，只有指针变化才重新下载 PO 表；校验行数、快照标识和唯一 PO／行键后原子更新参考字段。无需覆盖原工作区或重新初始化 Firebase。
- 保留已确认的 SAP PO 身份，同一 PO 内优先按物料匹配。物料唯一匹配不要求数量相等，数量差异仍独立核对。多个同物料候选依次使用匹配物料的原行号、已确认关联、唯一数量依据；无法确定时保留待关联。旧行号或旧关联不能盖过唯一 PO＋物料匹配。
- 确认对应后，仅将数值不同或缺失的 Line No 改为 SAP 行号。修正前值、该单元格公式及类型、SAP PO／物料、匹配依据和快照标识保存到 `row.sapLineCorrections`，不写入用户备注。只替换需要修正的 Line No 单元格及其公式，其他公式、评价、备注和人工记录不改。`sapLineCorrectionVersion=1` 标识新口径；同一 SAP 快照下的总表编辑也会重新核对，幂等轮询不反复保存。
- 自动关联的原始依据、SAP 行及编号规则存入工作区 `sapReferenceLinks/{generation}`，使用 ETag 防止并发覆盖。重新打开网页仍沿用对应关系；仅修改料号或数量不会额外制造行号差异。关联保存失败时不采用未保存的结果，保留上次成功参考并提示。
- Excel 侧来自当前 `importFields.po` 和 `importFields.line`。空白、`/`、`—`、`-` 都按缺失处理；纯数字标识忽略前导零和两端空白，但展示与导出保留原文。多 PO 文本不会擅自选择其中一个作为匹配结果。
- 共用 PO 合法；Excel 内同一 PO、同一物料、同一规范化行号出现多次时作为“Excel 记录重复待核对”，用于区分重复记录与拆分发运，不视为行号错误。不同物料指向同一 SAP 行只核对物料差异。旧行号异常关闭并保留备注和跟进记录。SAP 源内重复 PO／行键继续阻止快照应用并保留上次有效数据，多条 EKET 计划不属于重复 PO 行；多条关联仍不授权数量汇总。
- PO 存在但物料未匹配时，行号不动；有对应 SAP 行时展示双方行号与物料，不存在对应行时明确说明该 PO 下无匹配物料，不制造 SAP 行号或物料值。历史 OK／取消行也适用。
- Excel 状态为 OK 的记录不再生成“Excel 记录重复待核对”或“SAP 参考记录待关联”；旧事项自动结束并保留处理记录，不要求补充解释，不纳入未解决异常的计数、筛选及导出。状态改回 NG 后按当前事实重新检查。仅豁免这两类，取消状态或剩余数量为零不能替代 OK，真实物料号、PO 和单位异常仍独立核对。
- 不因 PO 编辑重新关联其他源记录。已完成、已取消行也参与比对。新增总表记录先显示待关联，不擅自用同料号猜测 SAP 订单。
- 导航按「备品备件表格 → 异常 → 待办 → 订单工作台」排列。异常默认显示全部记录，包括 OK、剩余待发为零及澳洲取消订单；待办单独显示交期、物流、价格与确认等跟进事项，默认显示当前待办。两个入口分别计数，筛选和导出只包含各自事项。OK 不等于 SAP 已收货。
- 修改保存后使用现有共享工作区机制重新计算异常。修正一致后异常自动关闭，再次变化会重新打开并保留跟进记录。仅填写备注不能关闭 PO 差异。读取参考数据失败时显示读取失败事项，已有 PO 差异不会误判通过；刷新页面可以重试读取。
- 异常列表以独立列并列显示双方 PO、订单行和料号，同时存在的 PO、料号差异都会高亮。六个表头均有 Filter 按钮，使用表头下拉搜索、多选、跨列叠加和清除筛选；筛选不更改业务记录。异常搜索支持双方 PO、订单行和料号；订单详情与导出均保留双方字段。异常 Excel 为 22 列，按当前筛选导出全部结果。
- 原导入的 `sap_link`、`material`、`price` 警告由动态规则替代。双方料号不同始终作为高优先级异常，即使已确认换算关系或总表标记 OK，也不会因此隐藏。价格确认归入待办。
- 物料号与单位分别核对，使用独立的 `material`、`unit` 事项、处理记录和导出行。已关联 SAP 的记录单位缺失／不同归为“单位待确认”，不会导致物料匹配失败；同时有两类问题则各占一条。物料事项仅显示物料比对，单位事项仅显示单位比对。演示的物料对应确认与单位换算也分开保存，真实导入数据需要核实源数据后重新核对。


## SAP 新增与总表评价（2026-10-12）

- SAP PO 查询沿用已配置的公司、工厂及供应商范围（示例为 3110／3111／0000003060）；网页读取同步服务发布的澳洲 PO 快照，不在浏览器里直接连接 SAP。最新中国 Excel 总表是比对基准，不能用旧初始化行替代新导入行。
- 每个经过完整性校验的新 SAP 快照，按上述 PO＋物料规则核对当前总表；只有缺少且同时通过日期及未收货 PO 口径的订单行才追加。日期必须严格晚于最新 Excel 最早有效订单日期，同日、更早或无效日期不补充；每次导入重新计算下限。未收货 PO 排除 `70000` 开头 PO、`D14` 开头物料、头／行删除 `L`、交货完成 `X`，并要求至少一条 EKET 计划数量大于 0 且剩余未收货大于 0。多计划按合格计划汇总，不覆盖。完整规则见 [Windows SAP 同步部署](RENDER-SAP-SETUP.md)。多候选保留为待关联，不把所有候选重复加单。
- 新增行在序号左上角显示 NEW。标记对应本次成功处理的 SAP 快照；相同快照的轮询或重新打开页面不会重复新增或清除标记，下一份快照只标记该次新增。换入新的中国文件后，即使 SAP 快照未变，也重新比较。
- 只为新增行填入 SAP 身份、描述、订购数量、下单日期，评价留空并显示蓝色待处理，不默认 NG；不推断 SAP 发运状态。人工处理或下一次 Excel 收录后，再沿用 NG／OK／澳洲取消订单状态。已有行仅允许上述 Line No 修正，其余单元格、公式、颜色、评价和备注不被 SAP 刷新改写，已有协作记录保留。NEW 和关联依据以行元数据保存，不写进序号或备注文本。
- 已存 SAP 补充后来不符合日期或未收货口径时，在总表、异常、待办及工作台隐藏，原记录保留，重新符合时恢复。Excel 原行始终保留，不受这些 SAP 补充筛选影响；其 OK／取消行依然参与物料号和 PO 比对，以及已授权的 Line No 修正。
- 评价编辑提供 NG（正在进行）、OK（完成）、澳洲取消订单。底层和 Excel 导出保留原状态代码。OK 行不再产生新的日常履约待办，身份与数据差异仍参与异常核对和导出。
- 自动追加使用工作簿现有 ETag 条件保存。并发冲突不会覆盖他人修改；未确认成功的版本不发布为新增结果，下次刷新读取最新版本再比对。SAP 失败沿用上次成功数据并保留失败提示。

## 未来四份 Excel 的输入边界

沿用主表、未完成清单、周发运、延期四种结构。准备脚本支持变化的日期文件名和任意主表行数；同角色有多个文件时拒绝猜选，可用 `--master`、`--open`、`--weekly`、`--delayed` 指定这次四个文件。每种表检查原有表头顺序，缺列或移列时停止导入，避免错读料号、PO、数量。补充表多次发运仍是原订单的观察记录；未唯一关联的补充记录作为独立待办展示和导出，不加入订单数量。

这不是任意格式自动识别，也没有取消既有工作区的覆盖保护：本轮未导入新文件、未增加网页四文件上传入口或自动替换整个历史工作区。新批次正式生效仍需通过导入流程，不能用旧行号强行合并新旧文件。正常 SAP 快照更新由网页自动核对。
